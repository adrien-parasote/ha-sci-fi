# Repo-wide guard: every test title cites only declared ids — Implementation Spec

Document Type: implementation

## Overview

Bead `ha-sci-fi-78y.8`, last child of `78y`. Seven lots (`78y.1`..`78y.7`) each cleaned the test titles of one perimeter and left a guard that holds only that perimeter. This lot adds one guard that holds the whole tree: every `it`, `test` or `describe` title under `tests/**/*.ts` (and `*.tsx`, none today) cites only ids that a spec declares as a row head, and the spec that declares an id is the one its NAME says: `docs/specs/NN_*.md` owns the bare ranges `TC-nnn` / `IT-nnn`, `docs/specs/cards/<card>.md` and `docs/MASTER.md` own the prefix derived from the file name (`prefixeAttendu` of `tests/specs/ids-cas-uniques.test.ts`: basename upper-cased, `_` to `-`), `docs/specs/<lot>/spec.md` owns the lot ids. Nothing is frozen: no list of ids, files, cards or counts; a spec that grows is judged by the same rule.

**The seven per-lot guards.** They stay as files. Only the cases the repo guard provably subsumes are retired (FR-10): vacuum loses its declared-ids case and its ghost fixture, bare-range loses its orphan-detector case, and the rows of those three cases stay in their closed lot specs marked `[RETIRED]`. Tv, water, weather, vehicles and alias lose nothing: each holds a narrower declared set for bare ids, a mutant a surviving case needs, or a check outside titles. The user chose to retire "now"; the author reads "provably" strictly, and the user may widen it.

**Read-only scan at SPEC (2026-11-02, worktree on `main`).** 115 test files, 1445 titles extracted with the TypeScript parser, no `.tsx`. Six cited tokens are undeclared, in five titles of four files (`vacuum-ids-declared.test.ts` carries two):

## Requirements

- **FR-1**: The guard lists the titles of a source text with `titlesOf(src: string, file: string): { titles: string[]; fragments: string[]; opaque: string[]; refused: string[] }`, built on the TypeScript parser (`import ts from 'typescript'`, a devDependency, no hand-written tokenizer: a regex or character scanner desynchronises on strings, comments and `.test(` calls, measured at SPEC). A title is the first argument of every call whose callee, followed down property accesses and calls, bottoms out on the identifier `it`, `test` or `describe`: so `it(`, `test(`, `describe(`, `it.each(table)(`, `describe.each(table)(` with a multi-line table, `it.skip(`, `it.only(`, `it.todo(`, `it.concurrent(`, `it.fails(`, `it.skipIf(c)(`, `it.runIf(c)(`, `it.skip.each(table)(` and any nesting inside `describe`. A string literal or no-substitution template gives its text; a template with `${}` gives its source text, where a `${ident}` span whose identifier is a same-file string `const` is replaced by that literal. The table argument of `.each(...)` is not a title. A `.test(` call on another object, the text of a string literal, a template or a comment are never titles. A first argument that is none of the above (an identifier, a concatenation) goes to `fragments`: the literal pieces found inside it, so ids written there are still read, and an identifier that the same file initialises with a string literal (`const T = '...'`) is resolved to that literal and read as a title. An argument still unresolved goes to `opaque`, and a renamed vitest import, a namespace import of `vitest` and a `const`/`let` aliasing `it`, `test` or `describe` go to `refused`; a literal piece of a fragment that ends in an id stem (`'TC-' + n`) is refused as a dynamic id; the guard on the tree must find both empty and a failure names the file and the entry (collected over the whole tree, never a throw that stops the scan). The root identifier counts unless a binding of that name encloses the call: a parameter, a `const`/`let`/`var`, function or class declared in an enclosing function, block or case clause, a `for` variable or a `catch` binding, between the call and the module scope (a binding elsewhere in the file does not hide the module-level `it`: `water-history-aligned.test.ts` binds `const it` inside a helper and keeps fifteen real titles at module scope; `delivered-design.test.ts` binds `const test` locally and its `test.includes(seg)` is no title) and does not rename it: `suite` and `bench` are roots as well, and an import of `it`, `test` or `describe` under another name (`import { it as t }`) is refused and named.
- **FR-2**: The corpus is the tracked-and-untracked-not-ignored files (`git ls-files -z -co --exclude-standard tests`, NUL-separated: a quoted path with non-ASCII bytes is never dropped) ending in `.ts` or `.tsx`, `tests/specs/` and the guard's own file included. Two witnesses, both derived, never a count written in the file: per file, `titles.length + fragments.length` is at least the number of lines that start (after blanks) with `it`, `test` or `describe` followed by `.` or `(`; and the number of files that carry at least one title is the number of files that carry at least one such line; a third witness reads the filesystem: every `*.test.ts` and `*.test.tsx` under `tests/` (`node_modules` excluded) is in the corpus, and one that is not is named (an ignored file that vitest still runs).
- **FR-3**: Every id token found in a title or in a fragment is a row head of at least one markdown file of `docs/` other than `docs/reviews/` and `docs/fixes/`. The id token is `(TC|IT|UT)-` followed by upper-case or digit segments joined by `-`, not preceded by a word character or `-`, not followed by one. A row head is a line whose first cell is the id, bold or not, with or without the ` ⬜` mark (the grammar of `LIGNE_ID` in `tests/specs/ids-cas-uniques.test.ts`). The failure message lists `file :: id :: title start` for each miss.
- **FR-4**: The owner of an id is read from its shape and must be the file that declares it, whatever the file that cites it. Bare `TC-n` / `IT-n` (digits only) are declared by a file matching `docs/specs/NN_<name>.md` and by no other; any test of any directory may cite them (the numbered specs are transverse: `tests/cards/weather/` cites spec 10, `tests/utils/` cites specs 03, 06 and 11, as today). `TC-<P>-U-n` and `IT-<P>-I-n` where `<P>` is the derived prefix of a `docs/specs/cards/<card>.md` or of `docs/MASTER.md` are declared by that file only; a lot spec (`docs/specs/<dir>/spec.md`, any `<dir>` other than `cards`) may not use a derived prefix; a markdown file anywhere under `docs/specs/cards/` other than `docs/specs/cards/<card>.md` is neither a card spec nor a lot spec and owns nothing. Any other `TC-<P>-U-n` / `IT-<P>-I-n` is a lot id and is declared by exactly one `docs/specs/<dir>/spec.md`. The derived prefixes are recomputed from the tracked files at each run. `TC` goes with `U` and `IT` with `I`, as `ids-cas-uniques` already demands of the cards.
- **FR-5**: A token the grammar of FR-4 cannot place is refused and named: a lowercase suffix (`TC-202b`), a segment-less or digit-less shape, and a template title that builds an id (`TC-${...}`, `IT-${...}`). Any upper-case `TC-`, `IT-` or `UT-` run of word characters and hyphens that holds a digit and is not exactly one token of FR-3 that FR-4 can place is refused and named too, whatever follows the digits: `TC-202bis`, `TC-202-old`, `TC-X-U-1_x`. Three forms are prose and never read, because current titles use them and FR-6 leaves them: a run that ends in a hyphen (a stem such as `TC-VACUUM-U-`), a digit run followed only by `x` (a wildcard such as `TC-7xx`, `TC-15xx`), and a lowercase prefix (`tc-202`). A digit-less run that is none of these (`TC-VE`) is refused as before; the builder re-runs the scan on the tree before writing the guard (the SPEC scan used the FR-3 token only, so it could not see these runs) and adds any other shape found here.
- **FR-6**: The five titles of the Overview table change and nothing else in their files does. `tests/cards/vacuum/vacuum-ids-declared.test.ts`: the title of `TC-VOI-U-10` reads `TC-VOI-U-10: the vacuum.md note names 1534 and 1535 and no unprefixed retired id` and the title of `TC-VOI-U-04` reads `TC-VOI-U-04: no vacuum test title carries an unprefixed TC-15xx, a retired VE id, TC-1016 or TC-506` (`TC-1016` and `TC-506` are declared bare ids; only `TC-VE` goes). `tests/cards/water/water-history-aligned.test.ts`: `TC-WSA-U-05: title is Spec 16 and the alerts filter row has no third filter`. `tests/docs/spec-numbering.test.ts`: `TC-RN-U-07: la note historique de stove.md nomme toujours les deux fichiers`. `tests/selectors/house.test.ts`: `TC-208: getAreasByFloor() returns [] when floor has no areas`. No test body, assertion or other title is edited by FR-6 (`vacuum-ids-declared.test.ts` also loses the two cases of FR-10, which is a separate edit of that file).
- **FR-7**: `docs/specs/02_domain_selectors.md` declares `TC-208` as a row head of its Test Cases table, type `Unit`, directly after `TC-207` and before `IT-201`: the scenario is `getAreasByFloor()` on an unknown floor id, the expected result an empty array, and `tests/selectors/house.test.ts` is named as the test. The test cell of the `F-DOM-04` feature row reads `tests/selectors/house.test.ts :: TC-201, TC-202, TC-205, TC-208, IT-203`. `TC-208` is declared once across `docs/`. (Written at SPEC, BUILD verifies.)
- **FR-8**: The guard is `tests/docs/repo-wide-ids-guard.test.ts` (not under `tests/specs/`: `ids-cas-uniques` ignores that folder when it looks for citations of declared ids, so the `TC-RWG-U-*` rows would count as uncited). Its test cases use the prefix `RWG` (`grep -rn RWG docs tests src` finds nothing at SPEC beyond this lot). It spells no id declared by a card spec or by `docs/MASTER.md`, and no id marked ⬜ anywhere: fixtures use ghost ids such as `TC-GHOSTRWG-U-01`, and ids that must exist are read from the tree or assembled from fragments. Reason: the O1 rule `malPlace` of `ids-cas-uniques` refuses a card id cited outside `tests/cards/<card>/` and a ⬜ id that a test spells stops being unplayed.
- **FR-9**: Every guard case that judges the tree also judges mutants: the same function applied to a fixture reports a ghost id, an id owned by the wrong class of file, a suffixed id, a dynamic id and each form of FR-1 (a guard that cannot fail proves nothing).
- **FR-10**: The repo guard takes over, in this lot, the "every cited id is declared" case of the per-lot guards it provably subsumes, and those cases are retired with it. A case is retired only when (a) every id its titles may cite is owned by the very file the repo guard names as owner (FR-4) and no surviving case lets a title cite an id of another owner, so the declared set it computes is the one the repo guard computes, (b) it holds no other assertion, and (c) no surviving case needs its helper or its mutant to be able to fail (FR-9). ## Anti-patterns

| # | Anti-pattern | Instead |
|---|---|---|
| 1 | Freezing a list of ids, cards, files or a count in the guard | Derive each from the tracked files, witnesses from a second probe |
| 2 | Extracting titles with a regex or a character scanner | The TypeScript parser (FR-1): `it.each` tables hold parentheses and strings hold `it(` |
| 3 | Widening the id grammar of `ids-cas-uniques` to read `TC-202b` | Refuse the suffix (FR-5); numeric ids only |
| 4 | Retiring a per-lot case that pins more than "cited ids are declared" (a narrower declared set, a prefix, a raw-text scan) | Keep it, and say what it pins (FR-10) |
| 5 | Citing an undeclared or ⬜ id literally in the guard | Ghost ids, fragments (FR-8) |
| 6 | Removing a retired case from a guard but leaving its row in the lot spec, or the reverse | Test and row leave in the same change; `ids-cas-uniques` is the witness |

## Error Handling

| Error | Response | Fallback | Logging |
|---|---|---|---|
| A title cites an id no doc declares | Guard fails listing `file :: id :: title start` | Add the spec row when the test asserts behaviour, else drop the id from the title | vitest output |
| An id is declared by the wrong class of file | Guard fails naming id, shape, declaring file, expected owner | Move the row to the owning spec | vitest output |
| A suffixed, dynamic or unplaceable id | Guard fails naming it | Number it plainly or drop it | vitest output |
| A test file parses to fewer titles than its line-start heads | Guard fails naming the file and both counts | Extend `titlesOf` for the new form (the own fixtures of the guard are single-line strings or use `
` escapes, because a fixture line that starts with `it(` raises the raw witness of FR-2) | vitest output |
| `typescript` cannot be imported | Suite fails at import | `npm install` | vitest output |
