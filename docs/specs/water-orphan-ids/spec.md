# Water test titles cite only declared ids — Implementation Spec

Document Type: implementation

## Overview

Bead `ha-sci-fi-78y.7`, child of `78y`; the repo-wide guard is `78y.8`. `tests/cards/water/sci-fi-water-management.test.ts` is the test of BOTH `docs/specs/cards/water.md` and `docs/specs/cards/water_history.md`. Twenty-eight of its titles cite 25 distinct bare ids that no spec declares: `TC-1201`..`TC-1205` (`TC-1203` on three titles), `IT-1201`..`IT-1205` (`IT-1201` on two titles, one as `IT-1201_primary`) and `TC-W01`..`TC-W15`. The user decided (chat, 2026-11-02): the specs gain one row per case, worded from what each test asserts, in the spec of the behaviour (one declaring document per id), and the titles take the prefixed ids that `tests/specs/ids-cas-uniques.test.ts` derives from the file name (`prefixeAttendu`: basename upper-cased, `_` to `-`: `water.md` gives `WATER`, `water_history.md` gives `WATER-HISTORY`). Numbers continue each table (`TC-WATER-U-009`.., `TC-WATER-HISTORY-U-006`.., `IT-WATER-HISTORY-I-004`..). The lot's own test cases use the prefix `WATOI` (`TC-WATOI-U-*`, `IT-WATOI-I-*`); `WOI`, `VOI`, `VEHOI`, `WSA` belong to other lots (`grep -rn 'WATOI' docs tests` finds nothing at SPEC).

**The split (user decision, 2026-11-02, after the adversarial review F-01).** The first version of this spec claimed the repo guards come back green with the 28 titles renamed in place. They do not: `ids-cas-uniques` O1 (`malPlace`, `tests/specs/ids-cas-uniques.test.ts:327-328`) refuses an id of a card spec that is cited from a file outside `cards/<spec basename>/`, and the basename of `water_history.md` is `water_history`. Twelve `water_history` ids (`TC-WATER-HISTORY-U-003`..`008`, `IT-WATER-HISTORY-I-004`..`009`) would be cited from `tests/cards/water/`, and no `tests/cards/water_history/` exists. The user chose to split the test: the thirteen history titles (rows 1..13) move, with their bodies unchanged, into `tests/cards/water_history/sci-fi-water-management-history.test.ts`; the fifteen water titles (rows 14..28) stay in `tests/cards/water/sci-fi-water-management.test.ts`. No repo guard is amended.

Decisions worth the user's eye. (a) Three existing history rows are taken (`TC-WATER-HISTORY-U-003`, `-004`, `-005`) and `TC-WATER-U-003` too: each duplicates a row's behaviour, so a second row would be the same case twice (spec-quality: one case per observation). `TC-WATER-HISTORY-U-001`, `-002` and `IT-WATER-HISTORY-I-001`..`003` are NOT taken: their tests would need a click, a sync count, a `start_time` or a render the present tests never assert, so they stay ⬜. (b) Rows 2, 10 and 11 pin the `expanded` trigger that `water.md` forbids (Known Gaps D21, bead `ha-sci-fi-xrc`); the rows say so and are the first to go when D21 is fixed. **No `Covers` cell cites them** (review F-03): a row that pins what a feature forbids is not coverage of that feature. (c) Row 13: the title says "only standalone" while the assertion expects both entities; the row follows the assertion and the title keeps its words (title-only rename). (d) **Row 1 loses `TC-WATER-U-007` from its title** (review F-06, and the split): the test never calls `_renderHistoryLogs`, so claiming it plays that row was false, and a `WATER` id cannot be cited from `cards/water_history/` anyway (O1). `TC-WATER-U-007` therefore takes ⬜ in `water.md` and says where its behaviour is asserted (`TC-WATER-HISTORY-U-003`, `-008`). Dropping the id from the title is the one title edit that is more than an id swap. (e) Rows 16/17 take the same id, as rows 3/5 do: ids-cas-uniques accepts several tests per id.

Enr lot interaction: `water_history.md` Known Gaps D14 said "TC-1205 pins the timestamp format while TC-WATER-HISTORY-U-005 is ⬜". ## Anti-patterns

| # | Anti-pattern | Instead |
|---|---|---|
| 1 | Declaring `TC-1201`, `IT-1203` or `TC-W03` as they are | Rename to the derived prefix: `TC-12nn`/`IT-12nn` are the numbered-spec family, `TC-Wnn` carries no card prefix |
| 2 | Writing a ⬜ row, or keeping ⬜ on a row a test now plays | A row played by a title carries no ⬜: ids-cas-uniques refuses the mismatch both ways |
| 3 | Giving a D21 test a row that reads as reference behaviour, or counting it in a `Covers` cell | The row names D21 and says it pins the code's legacy trigger; `water.md` forbids an accordion-open fetch, so no feature it forbids cites the row |
| 4 | Editing test bodies or comments while renaming or moving | Touch the title strings only; copy the block byte for byte |
| 5 | Putting the guard under `tests/specs/` | Keep it under `tests/cards/water/`: ids-cas-uniques ignores `tests/specs/` when it looks for citations |
| 6 | Naming the lot's own ids `TC-WOI-*` or `TC-WSA-*` | Those belong to the weather and arbitration lots; use `WATOI` |
| 7 | Letting the guard spell an `IT-WATOI-I-*` id, a retired id, or an id of either spec in full | The IT rows are ⬜ (played by command); retired ids and every `WATER` / `WATER-HISTORY` id are built from fragments: a literal in `tests/cards/water/` of a ⬜ id is "marqué ⬜ mais cité" and of a `water_history` id is O1 `malPlace` |

| 9 | Citing a card's ids from another card's directory | A `water_history` id is cited only from `tests/cards/water_history/`, a `water` id only from `tests/cards/water/` |

## Error Handling

| Error | Response | Fallback | Logging |
|---|---|---|---|
| A title cites an undeclared id | `toEqual([])` fails; the diff prints the file and the orphan ids | Drop the id or declare it | vitest output |
| A history id is cited from the water file, or a water id from the history file | TC-WATOI-U-01 fails naming the file; `ids-cas-uniques` O1 prints `<file> cite <id> (carte <carte>)` | Move the title to the file under `cards/<spec basename>/` | vitest output |
| A new row head is missing or doubled | `toEqual` on the heads array fails and prints the heads found | Fix the row | vitest output |
| A retired id is cited again | The empty-list assertion fails and prints the titles | Use the prefixed id | vitest output |
| A declared set reads empty | A `length > 0` assertion fails | Fix the row-head pattern | vitest output |
| The guard spells an id of either spec or an `IT-WATOI-I-*` id | TC-WATOI-U-10 fails; `ids-cas-uniques` fails on a stale ⬜ or on `malPlace` | Build it from fragments | vitest output |
| A moved test loses or gains a line | TC-WATOI-U-09 (counts) or IT-WATOI-I-01 (diff) fails | Re-copy the block from the base | command output |
