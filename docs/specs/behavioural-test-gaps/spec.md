## Requirements

- **FR-1** *(tv, user decision 2026-11-03: fixed in this lot, spec first)*: `SciFiTVCard._handleDrag` maps a pointer to a volume with `shiftedDeg = (thetaDeg + 135 + 360) % 360`, where `thetaDeg` is `atan2(svgY − 100, svgX − 100)` in SVG coordinates (y down). The rendered dial starts at `(46.97, 153.03)` (bottom-left, `thetaDeg = +135`) and sweeps 270° clockwise to the bottom-right, with its gap at the bottom (template comment "opening at bottom-center"; `computeDialGeometry` puts 0 % at 225° math-convention). **Measured with the code's own formula** (200×200 box): top → 0.17, right → 0.5, bottom → 0.83, left → 1, bottom-left (arc start) → **1**, bottom-right (arc end) → **0.67**, top-left → 0. On the rendered dial those points are 0.5, 0.83, (gap), 0.17, **0**, **1**. The formula places volume 0 at the top-left and the dead zone at the left, 180° from the drawing. `TC-TV-U-706` ("bottom centre → 1.0") and `IT-TV-I-703` ("60 % position → 0.6") cannot hold on today's code. The fix is `(thetaDeg − 135 + 360) % 360`. **Verified against the geometry, not only by arithmetic:** the rendered satellite of `computeDialGeometry` sits at `(100 + 75·cos a, 100 − 75·sin a)` with `a = 225° − v·270°`; feeding those points for `v` = 0, 0.17, 0.5, 0.6, 0.83, 1 to the corrected formula returns exactly `v` (round trip, measured with `node -e`); the arc start `(46.97, 153.03)` gives 0, the arc end 1, top 0.5, right 0.83, left 0.17. The gap is the bottom 90°: bottom-centre gives `shifted = 315`, which the existing clamp (`> 315` → 0, else 270) turns into `1.0`, the value `TC-TV-U-706` already states; a point at `theta = 100°` (gap, start side) gives 0, at `80°` (end side) gives 1. The clamp and the `/270` rounding are unchanged: `volumeLevel = Math.round((clampedDeg / 270) * 100) / 100`, clamp `shiftedDeg > 270 ? (shiftedDeg > 315 ? 0 : 270) : shiftedDeg`, so `shifted = 270` and `shifted = 315` both give 1 and `shifted > 315` gives 0 (agent's call: the volume is exact to two decimals, so tests assert with `toBe` on the rounded value, not `toBeCloseTo`). A test converts SVG units to pointer coordinates with `clientX = left + svgX / 200 * width`, `clientY = top + svgY / 200 * height`. `pointerdown` goes through `_handleDrag` and so through the throttle. The edit to `src/cards/tv/sci-fi-tv.ts` is this one expression plus the guards of FR-12 and FR-13 (family A).

- **FR-14** *(tv, user decision 2026-11-03: accept and pin; `F-05`)*: the dial is **angle-only by design** — the radius of the pointer is never read. A pointer on the volume readout (`.dial-label-container`, `pointer-events: none`, translated 42 px below the centre, so the tap lands on `.dial-svg`) therefore resolves in the bottom gap: a point at `x ≥ 100` (the vertical axis included) gives `1`, a point at `x < 100` gives `0` (measured with the corrected formula: `(100,152)` → 1, `(110,152)` → 1, `(90,152)` → 0). The readout points `(100,152)`, `(110,152)`, `(90,152)` (radius ≈ 52–53) now do nothing, pinned by `TC-BTG-U-22`.
- **FR-15** *(the "comments blanked" scan)*: the three ``css` `` greps (FR-6) blank comments with a **string-aware scanner** (`tests/helpers/blank-comments.ts`): a character-level state machine that tracks `'…'`, `"…"` and template literals (`${…}` nested) and blanks `//` and `/* */` only **outside** strings, so a `//` inside a string literal on the same line as a ``css` `` does not hide it. Its own fixture test is `TC-BTG-U-35`. API: `blankComments(src: string): string`, same length, comments replaced by spaces, so callers count ``css` `` with a regex afterwards; regex literals are out of scope (agent's call). A line-regex blanker (`//.*$`) is the mutant.
- **FR-16** *(strings render as text)*: state, name and title strings reach the DOM as text, never as markup. `TC-BTG-U-33` (tv) and `TC-BTG-U-34` (vacuum) set a hostile string (`<img src=x onerror=alert(1)>`) on the TV media title and friendly name, and on the vacuum friendly name and battery `unit_of_measurement`, then assert the shadow root holds **no** `img` element and the literal string is in the text content. BUILD first checks that the string reaches the DOM with a benign marker value (the field is rendered by the card in the state used), so the assertion cannot fail for an unrelated reason. The tv card renders the media title; the friendly name only where the template reads it (if it does not, that field is dropped from the test and the row says so).

## Reconciliation with BUILD (doc-update, 2026-11-03)

Additive notes; the requirements above stand. What BUILD did differently from the text:

- **Plan shape**: the build ran as one plan with atomic groups per family (A tv, B hexa-tiles, C vacuum, D climates + lights, E cross-card), not as five separate plans.
- **Guards edited outside any family write set**: `tests/cards/{tv,vacuum,vehicles,weather}/*-ids-declared.test.ts` now also accept the lot's own ids (`TC-BTG-U-NN`, `IT-BTG-I-NN`), read from this spec's table rows; without it the repo-wide ids guard flagged the new titles as undeclared. `tests/helpers/blank-comments.ts` (+ its test) is the shared comment blanker of FR-15.
