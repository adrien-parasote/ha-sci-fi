# French literals that never enter the translation circuit — Implementation Spec

Document Type: implementation

## Overview

Bead `ha-sci-fi-dp3` (retrocheck `j02`, 2026-10-31). The project's `sourceLocale` is `en`: a string a user reads must be an English `msg()` source, with its French in `xliff/fr.xlf` and `src/locales/locales/fr.js` (the contract C12 of [the stove spec](../cards/stove.md) states it). Some strings are written straight into the templates in French, so they show French in every language and no catalogue can reach them. The cards were built for Home Assistant users of every language; the workbench language switcher ([spec 09](../09_workbench_editor_i18n.md), `IT-901`) promises the opposite of what the lights card does.

**The census was re-measured on this tree (base `81c9d31`), and it differs from the bead's 56.** The bead's line numbers are stale (the stove, the climates `:44,:204,:336,:342,:348` and the hexa `:230` sites were fixed or moved since) and its probe counted comments. Two probes, both run here:

- *Accented, parsed.* A TypeScript AST walk of every `src/**/*.ts` file except `src/locales/`, over string literals and template parts, keeping those with an accented French letter that sit outside a `msg(...)` call: **34** raw hits. Five are not copy: four HTML comments inside the bridge templates (`<!-- ACCÈS … -->`, `<!-- ÉLECTROMÉNAGER -->`, `<!-- POÊLE & PELLETS -->`, `<!-- Liste toutes les personnes … -->`) and one CSS comment (`bridge/styles.ts`). **Left: 29 accent-bearing literals** — lights 18, climates 4, hexa-tiles 2, tv editor 3 (each is a template chunk holding one accented label), vehicles 1, weather 1.
- *Over-broad, read by hand* (static `label|title|text|placeholder` attributes, toast calls, text nodes, `??` fallbacks, a French function-word list): **8 French literals with no accent** — lights `'Tout allumer'` (inside `title="${houseActive ? 'Tout éteindre' : 'Tout allumer'}"`); tv editor `Bouton ${actionId}` and the dead fallback `'Configuration TV'` (`this.getSectionTitle('section-title-tv') ?? 'Configuration TV'`, `sci-fi-tv-editor.ts:141`); components `Type d'action (ex: call-service, navigate, none)`, `Service (ex: media_player.play_media)`, `Chemin de navigation`, `Nom de la source`, `Ajouter une source`.

**Census: 37 French literals outside `msg()` and the label dictionaries (29 accented + 8 unaccented), in 7 files across 6 cards and 2 components, plus 5 English sites the bead itself names or that share a block with them** (`'Hey, Welcome Back!'` hexa-tiles `:230`; the dead fallback `?? 'Sources'` tv editor `:216`; `Entity ID (data.entity_id)`, `title="Remove source"`, `label="Action"` in the two components). Total: **42 sites, 40 distinct sources: 33 new and 7 reused** (the reused: `No floor configured`, `Temperature changed`, `HVAC mode changed`, `Preset changed`, `Weather`, `Custom actions`, `Action`). Not counted and not touched: three water `msg()` calls whose *source* is French (`LOGS D'EXÉCUTION`, `Aucun événement enregistré.`, `Rafraîchir les logs`) and the unaccented French water sources (`Tout`, `Alertes`) — they sit inside the circuit, wrongly keyed; filed as a bead, see Assumption 6. The stove (`:392,401,410` in the bead) is already English `msg()` (O5); zero sites.

The fix is the documented contract, nothing invented: runtime strings are `msg('English')`; card-specific editor labels are keys of `src/cards/<card>/labels.ts` read by `this.getLabel(key)` ([ADR-017](../../adr/ADR-017_feature-first-modules.md)); French goes to the catalogue. A regression guard (FR-1) fails the suite the next time a French literal is written beside the circuit. Three specs are amended where the divergence is theirs: `lights.md` (no i18n clause), `hexa-tiles.md` (the French sentence `Alerte météo : canicule` inside an implementation contract), `09_workbench_editor_i18n.md` (`IT-901` promises `Lumières` and `Plafond` translate; `Plafond` is a registry area name, `Lumières` was a raw literal).

## Requirements

- **FR-1**: A guard `tests/i18n/no-hardcoded-literals.test.ts` fails when a file under `src/` (except `src/locales/`) holds, outside `msg(...)`, a French literal of the shape the detector `findFrenchLiterals(source: string, fileName: string): Finding[]` defines. The detector parses with the TypeScript compiler (never a line regex over the file) and flags:
  - (a) any string literal or template part that holds an accented French letter `[àâäçèéêëîïôöùûüÿœ]` (either case), after removing HTML comments `<!-- … -->` from the text;
  - (b) in a sink, any whole word of the French function-word list `le la les un une des du de d' l' aucun aucune ajouter pour cet cette ex: tout toute bouton` (case-insensitive, word boundaries, an apostrophe counting as a boundary). The sinks are: a static attribute `label|title|text|placeholder|aria-label` of an `html` template (the attribute scan spans newlines); a text node of an `html` template; **an expression `${…}` of an `html` template in an attribute value (`label|title|text|placeholder|aria-label`, with or without a `.` or `?` prefix) or in text position, where every string literal that is the whole expression or a branch of a ternary, of `??`, `||` or `&&`, parentheses and nested `html` templates followed, is judged**; the string arguments (ternary branches included) of a call named `_showToast`, `__toast` or `showToast`; the right side of `??`/`||` with a string.
  - It never reads comments, `css` tagged templates, `import`/`export` specifiers, type-level literals, or any literal that has a `msg(...)` call (or `str` template inside it) as ancestor, and it skips a file whose name ends `.fr-data.ts` (see exemption below). It reports file, line and text; on the real tree it reports nothing.
  - **Exemption (data, not copy).** A French string that is data (a French Home Assistant state value such as `Jaune`, a vendor enum) is written in a file named `*.fr-data.ts` beside its consumer and imported; that name pattern is the only exemption and is not a list of files. The failure message of the guard says so: `move the French data to a *.fr-data.ts file, or make the text an English msg() source (see spec i18n-hardcoded-fr FR-1)`.
  - **FR-1.1**: The scan reads every `*.ts` file of `src/` listed by `git ls-files -co --exclude-standard src` minus `src/locales/` (the repo idiom, `tests/blueprint-traceability.test.ts`), so a file added tomorrow, tracked or not, is judged and an ignored one is not; it fails if the list is empty, and an independent probe (the same list read with `fs` recursion minus ignored paths) must give the same set.
  - **FR-1.2 (the detector must prove it reads)**: a source with a TypeScript parse diagnostic is a failure, not a skip; the guard prints the count of files and string literals visited and fails if the literal count is zero or below the file count; and the detector is run over snapshots of the pre-fix files of `sci-fi-lights.ts` and `sf-editor-source-list.ts`, committed as `tests/i18n/fixtures/pre-fix/*.ts.txt` (not `.ts`, so neither the compiler nor the guard reads them; no dependency on git history, which a shallow CI clone lacks), which must give at least 19 and 2 findings (the census items of those files: lights 18 accented + `Tout allumer`; the source list `Nom de la source`, `Ajouter une source`).
- **FR-2**: `src/cards/lights/sci-fi-lights.ts` carries no French literal: its 19 are `msg()` English sources (table below), `Aucun étage configuré` reusing the existing source `No floor configured`; the default header is `msg('Lights')` (still replaced by `header_message` when set); the card re-renders on a locale change (it extends `SciFiBaseCard`, no new code). Each on/off pair (`isOn ? A : B`) is written with the sanctioned tuple lookup `[msg('B'), msg('A')][cond ? 1 : 0] as string` (spec 09 anti-pattern 6, already used at `sci-fi-tv.ts:554`), never as `cond ? msg('A') : msg('B')` (Anti-pattern 7).

Numbers on the base: the catalogue holds **326** units today and none is an orphan (measured at VERIFY: extract dropped nothing), so 326 + 33 = **359** after the lot; the measured number is the independent count of unique `msg()` ids of `src/`, the test compares to that only. Every one of the 40 census sources has a non-empty `<target>`; every one of the **33 new** sources has a `<target>` different from its `<source>` and (rule target ≠ source stays strict for them); the **7 reused** sources are exempt from the difference rule (their French is already committed and `Action` is the same word in both languages), the exempt list being the explicit constant of the test. Every target holds the same `<x id>` placeholders as its source (Builder Calls). The French wording of each new source is in Builder Calls.
- **FR-10**: Three specs are amended in place: `docs/specs/cards/lights.md` gains a `## Localization` clause (every user-visible string of the card is `msg()`, the keys of FR-2, and an editor label is a key of `labels.ts`); `docs/specs/cards/hexa-tiles.md` § "Alert Label" names the prefix as the localized `Weather alert:` (English) / `Alerte météo :` (French) and shows the result as `⚠️ Weather alert: canicule` in English and `⚠️ Alerte météo : canicule` in French; the row `IT-901` of `docs/specs/09_workbench_editor_i18n.md` reads `Lights card strings ("Lights", "Turn all off", the empty states) translate instantly to English; area names come from the Home Assistant registry and are not translated by the card` and states in its Expected that the hass reaching the card carries the new language (what the test asserts) and that the translation of the strings is proved by `IT-I18N-I-01` of this spec; its anti-pattern 3 gains the pointer to this lot's guard.
- **FR-11**: `makeMockHass` of `tests/fixtures/mock-hass.ts` accepts an optional `language?: string` override (default `'fr'`) that sets `locale.language`; an English assertion sets it and awaits `setLocale('en')` before rendering, as `tests/cards/stove/sci-fi-stove.test.ts` does for `fr`. The default does **not** make the existing tests safe: the card setter loads the locale fire-and-forget (`base-card.ts:40-46`) and Lit starts in `en`, so a French assertion on a string that becomes `msg()` races. **Three existing tests change**, and each awaits `setLocale('fr')` before mounting (and the file restores `fr` in `afterEach`): `tests/cards/lights/sci-fi-lights.test.ts:50` (`Aucun étage configuré`), `tests/cards/hexa-tiles/sci-fi-hexa-tiles.test.ts:591` and `:601` (`Alerte météo`, TC-HEXA-TILES-U-706/707). The builder greps `tests/` for any other French assertion on a converted string and amends it the same way, listing them in the build notes.
- **FR-12**: Anything French or English outside this census is not fixed here: it is a bead (Assumption 6). The lot touches no `dist/`, and adds no `msg()` to the bridge card.
- **FR-13** [ACCEPTED-LIMIT: decided by Adrien Parasote (the user) in the 2026-11-03 SPEC session; static analysis of free text cannot know an unaccented French word that is on no list, nor a French sentence assembled from several literals, and no test can pin a word nobody has listed]: after the widening of FR-1 (attribute and text expression branches, `tout`, `bouton`), the guard remains a regression net, not a proof of absence of French; the remaining blind spot is unaccented French not on the word list and French built from several literals; it is caught by review or by a card test, and the word list grows when a miss is found.

## Anti-patterns

| # | Anti-pattern | Instead |
|---|--------------|---------|
| 1 | Writing the French as the `msg()` source (`msg('Lumière éteinte')`) | English source, French in `xliff/fr.xlf` (C12: a French source id is absent from `fr.js` and falls back to itself in every language) |
| 2 | Putting a card's editor label inline in the editor | A key of `labels.ts`, read by `this.getLabel(key)` (ADR-017) |
| 3 | Translating in the test: asserting the French string on an English render | `makeMockHass({ language })` and `setLocale` for the language asserted |
| 4 | Concatenating translated pieces (`msg('Weather alert') + ' : ' + label`) | One `msg(str\`…${label}\`)`: French places its punctuation differently |
| 5 | Silencing the guard with an ignore list of files | Fix the literal; a literal that is not copy (HTML comment, CSS) is already outside the detector; French *data* goes to a `*.fr-data.ts` file (FR-1), a name pattern, not a list |
| 6 | Calling `msg()` in a component without `updateWhenLocaleChanges(this)` | The label would freeze at the locale of its first render |
| 7 | `cond ? msg('A') : msg('B')` (spec 09 anti-pattern 6: Terser collapses it into a dynamic `msg(cond ? …)` that breaks the XLIFF) | `[msg('B'), msg('A')][cond ? 1 : 0] as string` |

## Error Handling

| Error | Response | Fallback | Logging |
|-------|----------|----------|---------|
| A French literal is written outside `msg()` | The guard fails naming file, line, text and the remedy (`move the French data to a *.fr-data.ts file, or make the text an English msg() source`) | Make it an English `msg()` source, add the French to `fr.xlf`, rebuild; or, if it is data, a `*.fr-data.ts` file | vitest output |
| A source file does not parse | The guard fails naming the file and the diagnostic | Fix the syntax | vitest output |
| A `msg()` source has no `<trans-unit>` or an empty `<target>` | TC-I18N-U-11 fails naming the source | Run `localize-extract`, translate, run `localize-build` | vitest output |
| The locale is not loaded when a toast fires | `msg()` returns the English source | None needed: the source is a correct English sentence | none |
| The detector's function-word list hits an English literal | The guard fails on the real tree | Remove the word from the list (and its fixture), record it in the build notes | vitest output |
| `localize-extract` rewrites `fr.xlf` order or drops a unit | IT-I18N-I-04 shows a diff | Restore the unit; never hand-edit `fr.js` | VERIFY output |

## Builder Calls

Answers to a cold builder. Calls marked *mine* are the author's, not agreed with anyone; rulings marked *user* were given by the user.

- French wording of the new sources (*mine*, the user can correct it in review): `Mode applied` → `Mode appliqué`; `No lights configured for this floor` → `Aucune lumière configurée pour cet étage`; `Lights` → `Lumières`; `Turn all off` / `Turn all on` → `Tout éteindre` / `Tout allumer`; `Turn this floor off` / `on` → `Éteindre cet étage` / `Allumer cet étage`; `Select a room` → `Sélectionnez une pièce`; `Turn the room off` / `on` → `Éteindre la pièce` / `Allumer la pièce`; `No lights` → `Aucune lumière`; `Light turned off` / `on` → `Lumière éteinte` / `Lumière allumée`; `Room turned off` / `on` → `Pièce éteinte` / `Pièce allumée`; `Floor turned off` / `on` → `Étage éteint` / `Étage allumé`; `All turned off` / `on` → `Tout éteint` / `Tout allumé`; the hexa banner → `⚠️ Alerte météo : ${label}`; `Hey, Welcome Back!` → `Hey, bon retour !`; `Weather entity not found` → `Entité météo non trouvée`; `Volume entity` → `Entité Volume`; `Application entity` → `Entité Application` (the optional suffix is the existing `(optional)` → `(optionnel)`); `Button ${actionId}` → `Bouton ${actionId}`; `Action type (e.g. call-service, navigate, none)` → `Type d'action (ex: call-service, navigate, none)`; `Service (e.g. media_player.play_media)` → `Service (ex: media_player.play_media)`; `Entity ID (data.entity_id)` → `ID d'entité (data.entity_id)` (*user*); `Navigation path` → `Chemin de navigation`; `Source name` → `Nom de la source`; `Remove source` → `Supprimer la source`; `Add source` → `Ajouter une source`; `My vehicle` → `Mon véhicule`.
- Typography (*user* ruling: align with the catalogue): `ex:` has no space before the colon, as the catalogue's `(ex: water)` (`fr.xlf:929`); `(optional)` is never baked into a source.
- Placeholders in `fr.xlf` (the form `lit-localize` extracts, `fr.xlf:1193-1194`): a target repeats the source's `<x>` elements, not the text of the expression — `⚠️ Alerte météo : <x id="0" equiv-text="${label}"/>` and `Bouton <x id="0" equiv-text="${actionId}"/>`. A target carrying a literal `${label}` renders it as is in French; TC-I18N-U-18 refuses it.
- `fr.xlf` is edited by the tool then completed: run `npm run localize-extract`, which adds the units with an empty target (and would drop any orphan; the base had none), then fill each `<target>` with the French above, then `npm run localize-build`. The existing French of `No floor configured`, `Weather`, `Temperature changed`, `HVAC mode changed`, `Preset changed`, `Custom actions`, `Action` stays untouched (they are the 7 reused). There is no `N/A` unit in `fr.xlf`; nothing to remove.
- Detector (*mine*): `findFrenchLiterals` is a pure function exported from `tests/i18n/french-literals.ts` (a helper file, not a test), imported by the guard and by itself under test with inline fixtures; the sinks of FR-1 are matched on the AST: the `html` tagged template gives its static chunks (attribute scan, `${…}` replaced by a placeholder, spans newlines) and its `TemplateSpan` expressions (string-literal leaves through ternary, `??`, `||`, `&&`, parentheses and nested `html`), calls are matched by callee name. The French function-word list is a `const` of the helper, with a comment saying each word was chosen because the census used it. Fixture sources are inline strings; a fixture never spells a real census sentence in a way the guard would read in its own file (the guard reads `src/` only).
- Pre-fix controls (TC-I18N-U-17): the builder creates the two snapshots with `git show 81c9d31:<path> > tests/i18n/fixtures/pre-fix/<name>.ts.txt` once (agent's call: a CI clone may lack the commit). The fixtures are never edited.
- Real-tree hit outside the census (agent's call: FR-1 requires a green guard, so it wins over FR-12 for what the detector sees): the builder fixes it in this diff (English `msg()` + catalogue, or a `*.fr-data.ts` file if it is data), adds it to the build notes as a census addition; an English false positive removes the word (Error Handling).
